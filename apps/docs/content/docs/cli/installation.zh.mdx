## Installation

### 安装脚本 (macOS/Linux)

```bash
curl -fsSL https://cdn.leagent.me/computer/install.sh | bash
```

### Build from Source

```bash
git clone https://github.com/LRM-Teams/multica.git
cd multica
make build
mkdir -p "$HOME/.local/bin"
cp server/bin/multica "$HOME/.local/bin/multica"
export PATH="$HOME/.local/bin:$PATH"
```

### Download directly from the release feed

If the install script is not suitable for your environment, download the
release binary directly. This reads the same manifest `install.sh` uses, not
GitHub Releases. Requires `jq` or `python3` to parse the manifest.

```bash
OS=$(uname -s | tr '[:upper:]' '[:lower:]')   # "darwin" or "linux"
ARCH=$(uname -m)                                # "x86_64" or "arm64"

# Normalize architecture name
if [ "$ARCH" = "x86_64" ]; then
  ARCH="amd64"
fi
PLATFORM="${OS}-${ARCH}"

# Fetch the release manifest
curl -fsSL https://cdn.leagent.me/computer/manifest.json -o /tmp/multica-manifest.json
LATEST=$(jq -r '.tag' /tmp/multica-manifest.json)
URL=$(jq -r --arg p "$PLATFORM" '.platforms[$p].url' /tmp/multica-manifest.json)
SHA256=$(jq -r --arg p "$PLATFORM" '.platforms[$p].sha256' /tmp/multica-manifest.json)

# Download, verify, and extract
curl -sL "$URL" -o /tmp/multica.tar.gz
ACTUAL_SHA256=$(shasum -a 256 /tmp/multica.tar.gz 2>/dev/null | awk '{print $1}' || sha256sum /tmp/multica.tar.gz | awk '{print $1}')
if [ "$ACTUAL_SHA256" != "$SHA256" ]; then
  echo "Checksum mismatch: expected $SHA256, got $ACTUAL_SHA256" >&2
  exit 1
fi
tar -xzf /tmp/multica.tar.gz -C /tmp multica
mkdir -p "$HOME/.local/bin"
mv /tmp/multica "$HOME/.local/bin/multica"
chmod +x "$HOME/.local/bin/multica"
export PATH="$HOME/.local/bin:$PATH"
rm /tmp/multica.tar.gz /tmp/multica-manifest.json
```

`$HOME/.local/bin/multica` is the only supported macOS/Linux install target.
If an older installation resolves from another path, install the user-owned
binary first, put `$HOME/.local/bin` first on `PATH`, then have the machine
owner remove the old binary through the normal software-management process.

If a Computer is already running from the old path, it keeps that executable.
Wait until no agent task is running, then adopt the canonical binary and verify
the resident-reported version:

```bash
"$HOME/.local/bin/multica" computer restart
"$HOME/.local/bin/multica" computer status
"$HOME/.local/bin/multica" version
```

Adoption is complete when `computer status` reports the same `Version` as the
canonical `multica version`.

### Update

```bash
multica update
```

若 daemon 正在运行，`multica update` 会向该机器的受保护控制面提交一个
Machine Upgrade；daemon 是唯一负责 stage、handoff 和收敛的进程。daemon
不存在时，命令会锁定 VersionStore，安装 Active 版本供**下一次** daemon 启动使用，
不会声称已有运行中的 successor。若 PID 存在但控制面不可用，命令会以
`upgrade_service_unreachable` 拒绝离线绕过。


## Stuck on an old CLI (periodic self-update is retired)

Machine Upgrade is explicit-only. Older daemons (for example **0.3.64–0.3.x** installs) also cannot participate in the capability-gated lifecycle:

- the binary's compile-time release feed points at a dead URL
- the process is not a release build (`git describe` version), or is pinned

Do not wait for a background update. Use an **out-of-band** install from the public CDN release feed, then restart the daemon. Once it reconnects with a current daemon, use an explicit Machine Upgrade request for future upgrades.

首次从不支持 Machine Upgrade capability 的旧 resident 升级时，旧进程不具备 successor handoff 代码；完成带外安装后可能仍需一次显式 `multica computer restart`。在 capability-bearing successor 完整重新注册前，界面不会把这次 bootstrap 描述为已收敛完成。

### Runbook (macOS/Linux)

```bash
# 1) Install latest CLI into the canonical path (same as "Download directly")
curl -fsSL https://cdn.leagent.me/computer/install.sh | bash

# 2) Confirm the new binary
export PATH="$HOME/.local/bin:$PATH"
hash -r
multica version   # expect 0.4.x (or whatever manifest.json reports)

# 3) Adopt it for the machine-wide Computer (wait until no agent tasks)
multica computer restart

# 4) Confirm the daemon reports the same version
multica computer status
```

`MULTICA_DAEMON_AUTO_UPDATE`, `MULTICA_DAEMON_AUTO_UPDATE_INTERVAL`, `--no-auto-update`, and `--auto-update-interval` remain accepted temporarily for compatibility, but are no-ops. They cannot enable background release checks or mutation. `MULTICA_RELEASE_MANIFEST_BASE_URL` is still a release-source override used by explicit upgrade flows.

```bash
export MULTICA_RELEASE_MANIFEST_BASE_URL="https://cdn.leagent.me/computer"
```

Windows: download the `windows-amd64` zip from the selected channel manifest under the same CDN base URL, replace `multica.exe`, then run `multica computer restart`.

Do **not** change `server_url` to `https://…` until TLS to that host works from the machine (see ops notes for temporary `http://IP:port` configs).

## Quick Start

```bash
# One command: configure, authenticate, and start the Computer
multica setup /my-workspace
```

This selects fixed production, opens your browser for login, connects exactly one Workspace, and starts the machine-wide resident. For Tencent test use `--environment test --server-url <api-origin> --app-url <app-origin>`.

## Verify

```bash
multica computer status
```

Confirm:
1. Status is `running`
2. At least one agent is listed (e.g. `claude`, `codex`, `gemini`, `opencode`, `openclaw`, `hermes`, `kiro`, or `pi`)
3. At least one workspace is being watched

If the agents list is empty, install at least one supported AI agent CLI:
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code) (`claude`)
- [Codex](https://github.com/openai/codex) (`codex`)
- [Gemini CLI](https://github.com/google-gemini/gemini-cli) (`gemini`)
- OpenCode (`opencode`)
- OpenClaw (`openclaw`)
- Hermes (`hermes`)
- Kimi (`kimi`)
- Kiro CLI (`kiro-cli`)

Then restart the Computer:

```bash
multica computer restart
```
