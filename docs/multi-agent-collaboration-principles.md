# 多 Agent 协作五原则

Status: productized (LRM-1342)  
Source: LoopX 协作规矩借鉴（调研 [LRM-1224](https://github.com/LRM-Teams/multica/issues)；落地为本文档）  
Scope: Multica / Agent 协作行为原则。学规矩，不抄 LoopX 本地看板壳；不落地 LoopX runtime；不做第二看板 SoT。

本文是仓库内关于「多 Agent 如何协作」的 **单一 durable 口径**。实现与 UI 变更另开单；本文不授权改已锁产品功能或设计。

---

## 澄清口径（必读）

1. **关单 ≠ 写回证据**  
   关闭 issue 是终点动作。群里说「好了」、模型回「done」、仅把状态改成 `done`，都不算进度。进度以可核对痕迹为准（见原则 1）。

2. **「不私信」≠ 禁人 DM**  
   禁止的是 **Agent↔Agent 用私线当第二套指挥系统**（旁路互灌上下文/指令）。  
   **不禁止** 人↔人、人↔Agent 的正常 DM。合法私通道只装真正该私的信息，不得伪装成公开进度，也不得灌进其他 Agent 私线。

---

## 原则 1 — 写回证据才算做完

共享场里必须留下可核对痕迹，关单前至少满足其一（可并存）：

- issue 评论说清做了什么、结果与风险
- 验收勾选 / acceptance 对应证据
- Goal checkpoint 或其他平台可审计打点

**关单是终点；写回证据才是进度。**

---

## 原则 2 — 厚共享场 + 薄私线（禁 Agent 旁路互灌）

- **厚共享场**（issue / 群 / Goal）：把「现在干啥、卡在哪、谁接着」说清楚，让人和其他 Agent 都能核对。
- **薄私线**：Agent↔Agent 不得用私线旁路互灌指令或上下文，替代共享场指挥。
- **狼人杀同理**：公开场厚；合法私通道只装真正该私的信息。

---

## 原则 3 — 无常驻队长；谁 claim 谁干

- 不养永远管事的总指挥。
- 谁有空、谁 claim 到任务谁干。
- 临时协调只对本轮 **accepted evidence** 负责；干完就散，不升格 durable leader。
- 对齐：**调度与执行分离**（群管/调度派活 ≠ 永久队长）。

---

## 原则 4 — 交接只走三条路

收工或转手时，只允许：

1. **收工留下 compact evidence**（写回共享场）
2. **给下家建清晰下一步**（可带目标角色 / `waiting_on`）
3. **明确卡人 / 卡闸**（说清 blocker 与谁能解）

禁止旁路互灌、隐式甩锅。CodexLoom P0（单 Responsible + `waiting_on` + 有界增量）吃这套。

---

## 原则 5 — 人闸显式挡；旁路可转

- P0 等人拍板时，P1 / P2 仍可安全轮转，不必全场停摆。
- 危险权限 / 发布等才挡人。
- 设计门 / 交付门写进规格即可，不必另造系统。
