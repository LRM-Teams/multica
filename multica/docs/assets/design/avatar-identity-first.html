LRM-223 · 身份优先 · 单一 Avatar 定稿

已冻结 · 可验收 父单 LRM-81 Frank：不止血，直接走长期 B。对标 Slack：头像跟身份走，不跟每条消息载荷绑死。

定稿一句话

全产品只认一个 Avatar：入参是 actorType + actorId；用身份目录/缓存出图；消息上的 URL 只是加速；缺了不清空；失败画色圆字母，禁止整词文字。

占位：色圆 + 1～2 字母（显示名首字）。禁止「前端」「Agent」等整词塞进头像位。状态点不替代头像。

解析硬规则（对标 Slack）

  1. 按 actorKey 读进程缓存 / 身份目录
  2. 若消息带 avatarUrl → 刷新缓存（有值才写）
  3. 仍无 → 设计占位，后台拉目录；回来后同作者全表面更新
  4. 缺字段 / null / undefined 不得覆盖已有 URL

表面用法（全部同一组件）

给前端的实现要点

  • 入参主字段：actorType、actorId；avatarUrl?、name?、showStatusDot?
  • 全局 sticky：Map<actorKey, {url, initials, presence}>
  • 迁移顺序：气泡+Thread → 成员类 → 侧栏/@ → 收掉旧多套 Avatar
  • 本单不写代码；落地由前端子单（父 LRM-81）

验收清单

  • 群聊/DM 连续消息、WS 推送缺 URL：头像不闪、不变文字
  • 无头像作者：色圆字母占位，非整词
  • Agent：头像图 + 角标点（在线/忙碌/离线）
  • Members / 设置 / 资料卡与气泡视觉同源
