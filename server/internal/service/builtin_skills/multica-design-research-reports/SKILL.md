# 调研报告视觉策展

把报告当作一篇可探索的独立出版物，而不是应用后台、营销落地页或卡片集合。
先保证证据、引用和不确定性准确，再让视觉层次帮助读者理解。

Multica 的冻结 Manifest、报告 package 合同、证据边界和安全策略始终高于本 skill。
不得为了视觉效果修改主张、夸大置信度、隐藏反证或省略未解决问题。

`task_specific_schema.report_context` 是服务端冻结的唯一汇总入口。报告老板不等待
其他 Agent 聊天转述：`input_documents` 已包含各 Agent 持久提交的完整阶段结果，
`direction_coverage` 说明每个一级研究方向的代表节点与收敛状态。必须逐方向使用服务端
选定的最高层级节点；同一方向不得再重复展开已被它吸收的 S/M/L/XL，跨方向共享的
successor 也只能叙述一次。`converging` 表示最高层还有并列候选，`researching` 表示
尚无稳定节点，`active_work_count` 表示该方向仍在运行的任务数，三者都必须作为过程
状态展示，不能自行挑选额外输入补齐。`producer_name` 是代表节点的产出 Agent，
可以用于解释协作来源，但不能替代证据引用。

制作文件前，必须读取 `references/design-language.md`。只有需要核对实现来源或
第三方授权时才读取另外两个 references 文件。

## 1. 建立设计档案

读取冻结 Manifest 和已授权输入后，在工作文件中写一段 `Design Dossier`，至少包含：

- `reading_job`：读者主要要做的事，例如决策、比较、审计、理解演进或探索全貌。
- `evidence_shape`：材料的主要形态，例如时间线、对照矩阵、因果链、分类图谱、风险档案或叙事综述。
- `maturity`：`interim` 或 `final`。存在未完成 Work、未解决缺口或尚未发布时必须是 `interim`。
- `layout_family`：从参考文件的布局家族中选择一个最匹配的，不得固定使用默认值。
- `signature_motif`：只选一个贯穿全文的内容相关母题，例如轨迹、层级、注释线、证据印章或坐标轴。
- `density`、`motion`、`accent`：基于受众和材料决定，不得照搬上一份无关报告。
- `design_reason`：用一句话说明这些选择如何帮助理解本报告。

把该档案以安全的 HTML 注释放在文档开头：

```html
<!-- multica-design-dossier:v1
reading_job=compare; evidence_shape=matrix; maturity=interim;
layout_family=comparative-brief; signature_motif=annotated-axis;
density=compact; motion=restrained; accent=amber;
design_reason=用同一坐标系比较竞争方案并显式标出证据缺口。
-->
```

这是设计连续性的记录，不得放入隐藏推理、凭据、内部标识符或敏感内容。

## 2. 让每份报告有自己的特点

从内容推导差异，不要随机换皮。每份新报告至少要在下列五项中形成三项明确、
可观察的差异：

1. 页面构图与章节节奏。
2. 标题与正文的字型角色分工。
3. 信息密度与留白策略。
4. 一个内容相关的视觉母题。
5. 数据、证据和引用的表达方式。

不要把“独特”理解成增加装饰。两个主题相近、受众相同、证据形态相同的报告可以
共享布局家族，但必须由各自内容决定标题节奏、关键视觉、章节重心和证据呈现。

禁止默认输出：紫色 AI 渐变、深色网格背景、居中大标题加三张等宽卡片、满屏玻璃态、
每个区块同样圆角、无意义发光、循环漂浮动画，以及把所有正文塞进卡片。

## 3. 表达调研成熟度

`interim` 报告必须在首屏清楚标明“阶段性调研结果”，同时展示：

- 当前覆盖范围与尚未覆盖范围。
- 已验证、待验证、存在争议的结论数量或分组。
- 最近纳入的阶段性成果。
- 下一步仍在进行的方向。

不得用“最终结论”“完整报告”等文案伪装完成。中间结果可精美，但必须显得正在生长：
使用进度脉络、开放问题、证据状态和更新时间，而不是加载骨架或假进度条。

`final` 报告仍要保留限制、反证和方法说明；最终状态不等于绝对确定。

## 4. 组织独立报告页面

根据 Design Dossier 重新编排，而不是机械套用固定章节。通常应覆盖：

- 报告标题、范围、状态与一句话结论。
- 关键发现及其证据强度。
- 适合材料形态的主体叙事或比较结构。
- 方法、来源覆盖与引用。
- 反证、争议、限制和开放问题。
- 对决策的影响与下一步。

允许章节顺序和视觉权重随阅读任务变化。重要结论必须能回到引用；装饰元素不得
伪装成数据。图表必须包含文字结论、单位、范围和来源，不得只靠颜色传达含义。

## 5. 保持修订连续

修订已有报告时，先读取 `report_context.supersedes.design_dossier` 中由服务端验收并
持久化的上一版 Design Dossier。默认保留布局家族、母题、
字体角色、颜色逻辑和导航习惯，只更新内容、状态、图表与必要的章节结构。

只有以下情况可以重做视觉语言：用户明确要求；质量审查指出可用性问题；报告的
阅读任务或证据形态发生根本变化。重做时在新档案的 `design_reason` 中说明原因。

不得因为一次增量结果就整页换主题，也不得复制另一份报告的档案作为捷径。

## 6. 遵守 package 与安全边界

- 只使用报告 package 中上传并验证的 HTML、CSS、脚本、图片和字体。
- 不引用外部 URL、CDN、远程字体、应用同源资源或未上传的本地路径。
- 不使用表单、iframe、弹窗、下载、存储、网络请求、Worker 或父页面 bridge。
- 优先使用语义 HTML 和 CSS；只有交互确实提升阅读时才加入小型脚本。
- 保持键盘可达、清晰焦点、可读对比度、响应式布局和减少动态偏好。
- 生成完整纯文本、outline 和 citations；它们必须与页面实际内容一致。
- 先完成并检查全部资源，再执行不可逆的正式提交；不要发送探测 payload。

## 7. 提交前检查

逐项确认：

- 首屏是否说明主题、范围和 `interim` / `final` 状态？
- 设计档案是否由本报告内容推导，并在至少三项上形成可观察特征？
- 是否存在默认卡片网格、装饰性噪声或与内容无关的动效？
- 每个重要结论、数字和图表是否有可追溯证据？
- 反证、限制和开放问题是否与主结论同样容易发现？
- 长标题、长 URL、窄屏、键盘操作和减少动态模式是否可用？
- 页面是否完全自包含并符合 V6 报告安全合同？

任一项失败时先修复报告，不要提交 package。
