# Runtimes source map

- `server/cmd/multica/cmd_runtime.go` registers runtime list, usage, and activity.
- `server/cmd/multica/cmd_computer.go` registers the machine-wide Computer lifecycle (`start`/`stop`/`restart`/`status`/`logs`), `doctor` diagnostics, and the only local upgrade entry point. For a live Computer it creates the canonical Machine Upgrade with the saved human session; the server dispatches it over the current Binding socket. `cmd_computer_upgrade_progress.go` waits by default and renders the Host's actual upgrade phases plus successor health/Workspace reconnection; `--no-wait` returns after submission. `server/internal/computer/lifecycle_upgrade.go` owns service-first routing, absent-resident offline installation, and live-unreachable fail-closed behavior. Its retired-flag guard applies to lifecycle commands; setup reuses only the retired `--profile` check. `computer upgrade` swaps `$HOME/.local/bin/multica` via `cli.SwapExecutable` (`server/internal/cli/exec_swap.go`). Start/supervise use that same path.
- `server/cmd/multica/cmd_setup.go` owns and accepts `--environment test --server-url <api-origin> --app-url <app-origin>`, reuses saved Test origins for idempotent repair setup, asks before switching an already-active environment, validates the target before side effects, establishes one Workspace connection with Workspace-scoped authorization, ensures the resident is running without restarting a healthy matching process, and requires both the resident IPC health Workspace ID list and the authenticated server Computer projection to prove that selected connection is live.
- `server/internal/daemon/workspace_daemon_state.go` sends Computer device name, OS, and CLI version in the authenticated WorkspaceDaemon `ready` frame; `server/internal/handler/runner_activity.go`, migration 418, and `computer_projection.go` persist and project that metadata independently of provider Runtime rows.
- `server/cmd/multica/cmd_config_use.go` switches an already-configured production/test environment together with its matching package, requires confirmation before interrupting a running resident, and supports explicit `--yes` automation.
- `server/internal/cli/service_environment.go` owns the production/test service-target contract; `release_channel.go` and `update.go` derive the matching stable/preview entry from the canonical `metainfo.json`.
- `server/cmd/multica/cmd_daemon.go` registers the hidden, deprecated `daemon` lifecycle aliases that delegate to the same machine-wide Computer and emit deprecation guidance.
- `server/internal/computer` owns the machine-wide Computer lifecycle (identity, environment-keyed Workspace connections, process, state layout, health, diagnostics) that the Computer and the hidden daemon aliases both drive. `server/cmd/multica/cmd_terminal_progress.go` renders lifecycle progress as colored TTY spinners or stable redirected plain text. `computer.go` owns graceful stop and its forced fallback; after killing an unreachable Computer, the fallback uses persisted WorkspaceDaemon process state and the reclamation fence to terminate every orphaned WorkspaceDaemon before reporting success. `cmd_computer.go` and `machine_upgrade_detached.go` route same-binary Restart through `computer __restart`, whose handoff waits for predecessor processes and starts the current binary without reading or creating a Machine Upgrade journal. `machine_upgrade.go` consumes already-created server operation IDs from loopback or WorkspaceDaemon delivery; it does not create human operations with Workspace execution credentials.
- `server/cmd/server/router.go` registers daemon task claim, runtime APIs, and `POST /api/daemons/{daemonId}/upgrades` socket dispatch.
- `server/internal/handler/machine_upgrade_handler.go` authorizes the Computer owner from the active Workspace Binding and sends `computer:upgrade` on one current Binding socket. Runtime cardinality and metadata do not gate this machine-wide operation. Progress and completion come back on that socket; there is no cloud receipt table.
- `server/pkg/protocol/events.go` and `packages/core/types/events.ts` define the `computer:updated` event contract; `packages/core/realtime/use-realtime-sync.ts` invalidates the Workspace Computer/Runtime query prefix on receipt.
- `server/internal/computer/machine_upgrade.go` owns the durable local Machine Upgrade journal, exact rollback, and fail-closed startup recovery. A successor proves its exact local binary and generation; Runtime registration remains post-handoff convergence evidence. Only a proven later Active generation may supersede a retained `candidate_ready` marker.
- `server/internal/daemon/daemon.go` claims tasks, enters the durable Agent workspace, launches provider CLIs, and reports completion.
- `server/internal/daemon/execenv/agent_workspace.go` defines the canonical Agent workspace layout.
