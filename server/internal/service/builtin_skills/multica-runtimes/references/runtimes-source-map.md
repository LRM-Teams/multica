# Runtimes source map

- `server/cmd/multica/cmd_runtime.go` registers runtime list, usage, and activity.
- `server/cmd/multica/cmd_computer.go` registers the machine-wide Computer lifecycle (`start`/`stop`/`restart`/`status`/`logs`), `doctor` diagnostics, and the only local upgrade entry point. `server/internal/computer/diagnose.go` keeps doctor read-only by default; explicit `--fix` reports each successful cleanup while removing a confirmed-stopped stale resident PID, deleting upgrade staging older than 24 hours, and quarantining per-Binding coordinator state older than 24 hours when no corresponding Binding exists. For a live Computer, `computer upgrade` creates the canonical Machine Upgrade with the saved human session before sending the same operation ID to Host loopback; `server/internal/computer/lifecycle_upgrade.go` owns that service-first delivery, absent-resident offline installation, and live-unreachable fail-closed behavior. Host and Daemon WS deliveries converge on the same operation ID. Its retired-flag guard applies to lifecycle commands; setup reuses only the retired `--profile` check. `computer upgrade` swaps `$HOME/.local/bin/multica` via `cli.SwapExecutable` (`server/internal/cli/exec_swap.go`). Start/supervise use that same path.
- `server/cmd/multica/cmd_setup.go` owns and accepts `--environment test --server-url <api-origin> --app-url <app-origin>`, reuses saved Test origins for repair setup, asks before switching an already-active environment, validates the target before side effects, establishes one Workspace connection with Workspace-scoped authorization, and starts the resident.
- `server/cmd/multica/cmd_config_use.go` switches an already-configured production/test environment together with its matching package, requires confirmation before interrupting a running resident, and supports explicit `--yes` automation.
- `server/internal/cli/service_environment.go` owns the production/test service-target contract; `release_channel.go` and `update.go` derive the matching stable/preview entry from the canonical `metainfo.json`.
- `server/cmd/multica/cmd_daemon.go` registers the hidden, deprecated `daemon` lifecycle aliases that delegate to the same machine-wide Computer and emit deprecation guidance.
- `server/internal/computer` owns the machine-wide resident lifecycle (identity, environment-keyed Workspace connections, process, state layout, health, diagnostics) that the Computer and the hidden daemon aliases both drive. `host_machine_upgrade.go` consumes already-created server operation IDs from loopback or Binding child delivery; it does not create human operations with Workspace execution credentials.
- `server/cmd/server/router.go` registers daemon task claim, runtime APIs, and `POST /api/daemons/{daemonId}/upgrades` socket dispatch.
- `server/internal/handler/machine_upgrade_handler.go` authorizes the Computer owner and sends `computer:upgrade` on one current Binding socket. Progress and completion come back on that socket; there is no cloud receipt table.
- `server/pkg/protocol/events.go` and `packages/core/types/events.ts` define the `computer:updated` event contract; `packages/core/realtime/use-realtime-sync.ts` invalidates the Workspace Computer/Runtime query prefix on receipt.
- `server/internal/daemon/machine_upgrade.go`, `machine_upgrade_takeover.go`, and `machine_upgrade_recovery.go` own the durable local Machine Upgrade journal, local-first detached candidate proof, exact rollback, and fail-closed startup recovery. `server/cmd/multica/machine_upgrade_detached.go` owns the candidate-generation-bound local launcher/candidate protocol marker and the pre-v2 loopback compatibility handshake. A detached candidate proves Computer generation and accepted Workspace bindings locally; Runtime registration remains post-handoff convergence evidence. Only a proven later Active generation may supersede a retained `candidate_ready` marker.
- `server/internal/daemon/daemon.go` claims tasks, enters the durable Agent workspace, launches provider CLIs, and reports completion.
- `server/internal/daemon/execenv/agent_workspace.go` defines the canonical Agent workspace layout.
